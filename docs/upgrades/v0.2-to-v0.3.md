# Upgrade Guide: v0.2.x → v0.3.0

> **Released**: _target TBD_
> **Severity**: ⚠️ Breaking — DB schema change for `executions` table
> partitioning. **Read fully before upgrading**.

## Summary

v0.3.0 introduces **monthly partitioning** on the `executions` table to
keep long-running installations fast. This requires a one-time
migration that copies data into partitioned tables.

Estimated migration time:
- < 1M rows: < 5 minutes
- 1M–10M rows: 5–30 minutes
- > 10M rows: use the parallel migration path (below)

## Breaking changes

### `executions` table is now partitioned

```sql
-- Old (v0.2.x)
CREATE TABLE executions (
  id UUID PRIMARY KEY,
  workspace_id UUID NOT NULL,
  ...
  created_at TIMESTAMPTZ NOT NULL
);

-- New (v0.3.0)
CREATE TABLE executions (
  id UUID NOT NULL,
  workspace_id UUID NOT NULL,
  ...
  created_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);

CREATE TABLE executions_2026_07 PARTITION OF executions
  FOR VALUES FROM ('2026-07-01') TO ('2026-08-01');
-- ...one partition per month
```

**Implication**: if your queries use `id` alone (without `created_at`),
they will be slow (full partition scan). See **Migration step 4**.

### `archivedAt` column added

Adds nullable `archived_at TIMESTAMPTZ`. Index added for archival
queries.

## Step-by-step migration

### 1. Pre-flight: take a fresh backup

```bash
# PostgreSQL logical backup
pg_dump --format=custom --jobs=4 "$DATABASE_URL" \
  > backups/before-v0.3.0-$(date +%Y%m%d).dump
```

### 2. Stop writers

```bash
# Scale down API + worker
kubectl scale deploy/maximilian-api --replicas=0
kubectl scale deploy/maximilian-worker --replicas=0
```

### 3. Run the migration

For small DBs (< 1M rows), the default migration is fine:

```bash
pnpm --filter @max/database migrate
```

For larger DBs, use parallel migration:

```bash
pnpm --filter @max/database migrate -- --parallel --jobs=4
```

The migration:
1. Creates new partitioned `executions` table.
2. Copies data in chunks.
3. Adds `archived_at` column + index.
4. Atomically renames `executions` → `executions_old`,
   `executions_new` → `executions`.
5. Leaves `executions_old` for 30 days, then drops it (cron job).

### 4. Verify query performance

```sql
-- Should be fast (uses partition pruning)
EXPLAIN SELECT * FROM executions
WHERE created_at >= '2026-07-01' AND created_at < '2026-08-01';

-- ⚠️ Will be slow without created_at filter
EXPLAIN SELECT * FROM executions WHERE id = 'some-uuid';
```

If you have queries that look up by `id` alone (no `created_at`),
consider adding `created_at` to the WHERE clause, or create a
non-partitioned lookup index:

```sql
CREATE INDEX idx_executions_id_only ON executions (id);
```

### 5. Restart writers

```bash
kubectl scale deploy/maximilian-api --replicas=2
kubectl scale deploy/maximilian-worker --replicas=1
```

### 6. Monitor for a week

Watch the dashboard `DB Pool` and `Query Latency`. If you see
regressions, see **Rollback** below.

## Rollback

If query performance regresses, downgrade v0.3.0 → v0.2.x:

```bash
# 1. Stop writers
kubectl scale deploy/maximilian-api --replicas=0

# 2. Rename tables back
psql "$DATABASE_URL" <<EOF
ALTER TABLE executions RENAME TO executions_partitioned;
ALTER TABLE executions_old RENAME TO executions;
EOF

# 3. Downgrade code
git checkout v0.2.x
kubectl apply -f k8s/

# 4. Restart
kubectl scale deploy/maximilian-api --replicas=2
```

The old code reads the non-partitioned table fine.

## Common errors

### `Error: partition already exists for range ...`

You ran the migration twice. The migration is idempotent for
partition creation, but if you see this in the logs, it's a warning —
not an error.

### `Migration timeout after 30 minutes`

For very large tables. Use the parallel flag (step 3) or increase the
statement timeout:

```bash
psql "$DATABASE_URL" -c "SET statement_timeout = '2h';"
pnpm --filter @max/database migrate
```

## What didn't change

- HTTP API surface — unchanged.
- All other tables (`users`, `workspaces`, `metrics`, etc.) — unchanged.
- TruthAudit, Digital Twin, Meta-system — unchanged.
- Configuration files — unchanged.
