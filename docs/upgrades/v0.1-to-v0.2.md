# Upgrade Guide: v0.1.x → v0.2.0

> **Released**: _target TBD_
> **Severity**: ⚠️ Breaking — environment variable renames + new
> required variables. Read fully before upgrading.

## Summary

v0.2.0 reorganizes environment variables for clarity and adds required
configuration for the new TruthAudit and Digital Twin subsystems.

The good news: most of these are **rename-only**, no code changes are
required if you used the documented defaults.

## Breaking changes

### Environment variable renames

| Old (v0.1.x) | New (v0.2.0) | Notes |
|---|---|---|
| `META_AGENT` | `META_AGENT_ENABLED` | Boolean flag, was implicit `true` |
| `DIGITAL_TWIN` | `DIGITAL_TWIN_ENABLED` | Same |
| `EVOLUTION` | `EVOLUTION_ENABLED` | Same |
| `LLM_PROVIDER_DEFAULT` | `LLM_DEFAULT_PROVIDER` | Renamed for consistency |

**Why**: we standardized on `*_ENABLED` suffix for feature flags and
`LLM_*` prefix for LLM config.

### New required variables

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `TRUTH_AUDIT_ENABLED` | no | `false` | Enable TruthAudit persistence |
| `TRUTH_AUDIT_MIN_SAMPLES` | no | `3` | Min samples before verification |

`TRUTH_AUDIT_ENABLED` defaults to `false` so existing installations
are not affected.

## Step-by-step migration

### 1. Update your `.env` file

```diff
- META_AGENT=true
+ META_AGENT_ENABLED=true
- DIGITAL_TWIN=true
+ DIGITAL_TWIN_ENABLED=true
- EVOLUTION=true
+ EVOLUTION_ENABLED=true
- LLM_PROVIDER_DEFAULT=anthropic
+ LLM_DEFAULT_PROVIDER=anthropic
```

### 2. Verify the rename worked

```bash
pnpm --filter @max/api config:check
```

This command (added in v0.2.0) prints a table of every env var it
loaded, and warns about any deprecated names still in use.

### 3. (Optional) Enable TruthAudit

If you want to use the new TruthAudit feature:

```bash
TRUTH_AUDIT_ENABLED=true
TRUTH_AUDIT_MIN_SAMPLES=3   # default, fine for most cases
```

Then run the migration:

```bash
pnpm --filter @max/database migrate
```

This adds the `truth_measurements` table (see [RFC-0001](../rfcs/0001-truth-audit.md)).

### 4. Restart the API + worker

```bash
# If using docker-compose
docker compose restart api worker

# If using k8s
kubectl rollout restart deploy/maximilian-api deploy/maximilian-worker
```

### 5. Verify

```bash
# Health check
curl http://localhost:3000/healthz
# Should return 200 with "status: ok"

# TruthAudit check (if enabled)
curl http://localhost:3000/v1/meta-system/truth-report
# Should return 200 with report JSON
```

## Rollback

If something goes wrong, v0.2.0 → v0.1.x is a downgrade:

```bash
# Stop the new version
docker compose down

# Restore old env vars (opposite of step 1)
git checkout v0.1.x -- .env

# Start the old version
docker compose up -d
```

The `truth_measurements` table is **additive** — leaving it in the
database after a downgrade does no harm; the old code ignores it.

## Common errors

### `Error: META_AGENT_ENABLED must be "true" or "false"`

You forgot to rename. Either update `.env` or set the old var:

```bash
# Old (still works in v0.2.0 with a warning):
META_AGENT=true

# Better:
META_AGENT_ENABLED=true
```

### `Error: truth_measurements table does not exist`

You enabled `TRUTH_AUDIT_ENABLED=true` but did not run migrations:

```bash
pnpm --filter @max/database migrate
```

## What didn't change

For reassurance, here is what stayed the same:

- HTTP API surface — all routes in `/v1/*` unchanged.
- Database schema for `users`, `workspaces`, `executions`, `metrics`,
  `evolution_events`, `org_events` — no changes.
- Configuration file format (`config/providers.json`).
- Default ports (API 3000, worker 3001, dashboard 5173).
- Docker image names.
- Package names (`@max/*`).
