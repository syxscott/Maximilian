# 2026-06-27 — Code-review bug fixes (8 bugs)

**Status**: ✅ Completed (one-shot session)

After the OpenAPI · Audit Log · Pagination · SSE Reconnect session, a
follow-up code review surfaced 8 bugs in the freshly-written code. All
fixed in this session. The bugs cluster into three groups:

- **SSE stream correctness (1, 2, 3, 8)** — replay missed the snapshot,
  snapshots flooded the buffer, `done` double-fired on reconnect, and the
  frontend never gave up on a broken stream
- **Permission audit log (4, 6, 7)** — eviction broke lookup, `getByRequestId`
  semantics were wrong, and `total` returned page size instead of filtered count
- **OpenAPI coverage (5)** — one newly-defined route was never registered

## Behaviour summary

### SSE — before vs after

```
Before (broken):
  1. ws=completed → buffer holds [workspace, event, done]  (snapshot/done fill buffer)
  2. client reconnects with Last-Event-ID pointing at the last buffered event
  3. server replays 0 events, sends current ws, then sends done again  ← double done
  4. if buffer is full, real events get evicted before client sees them

After (fixed):
  1. ws=running, buffer holds only runtime events (64 cap)
  2. client reconnects
  3. server sends current ws snapshot first (ephemeral, no id)
  4. server replays events with id > lastEventId
  5. live runtime listener attaches
  6. terminal workspace: server sends one ephemeral done, closes
  7. client receives one done, closes its EventSource
```

### Permission audit log — before vs after

```
Before (broken):
  - eviction deletes requestLookup[r1] when ask row leaves
  - later: getByRequestId("r1") returns the row that happened to be there
  - audit endpoint reports total = items.length (page size)

After (fixed):
  - entries is the only source of truth
  - getByRequestId("r1") returns all matching rows (typically 2: ask + allow/deny)
  - audit endpoint reports total = countMatching(filter) over the full buffer
```

### Frontend SSE — before vs after

```
Before:
  onerror → (nothing) → browser auto-reconnects → onerror → (nothing) → ...

After:
  onmessage → sseErrorCount = 0
  onerror → sseErrorCount += 1
           → count < 5: log + retry (browser auto-reconnects, resends Last-Event-ID)
           → count >= 5: close EventSource, release submitting lock
```

## Non-goals (still deferred)

- The audit log is in-memory; a process restart loses it. The
  `PermissionAuditLog` class accepts a `persistPath` for JSON append-log
  durability but it's not wired in `apps/api/src/index.ts` yet.
- `SseReplayBuffer` is per-process. A client reconnecting to a different
  API worker won't see missed events. Acceptable at current scale; if we
  ever shard workers, the buffer will move to Redis.
